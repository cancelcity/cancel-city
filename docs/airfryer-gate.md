# Airfryer Gate — first neighbourhood case

The city opens on its existing illustration with one story invitation. Building management appears on selection. Airfryer Gate connects a local incident to an original receipt, a four-statement Screenshot Court hearing and a lasting sign on the Palace.

Three irreversible responses create different starting pressure, credibility, evidence and rewards. Court statements have exact forecasts. Evidence strengthens a counter-accusation; unsupported accusations backfire. The final pressure and credibility determine one of three endings. Each ending changes the Palace sign and resident relationship text. All outcomes grant a finite, atomic reward.

The optional `airfryer` save field defaults to an untouched case when reading older saves. The shared command processor and Worker schema enforce phases, affordability, rounds, single-use statements and idempotency. Save validation replays the argument history to check counters and requires reward markers to match the route and verdict. No new database table, external model, character art or runtime asset is required.

The false roommate rewards, frozen scandal timer, independent heat counter, unconditional raid alert and canned live feed have been removed from the city presentation. Existing jobs and incidents remain in Drama and the directory. Sponsor actions now grant their advertised rewards once per UTC day. Rival bounties are fixed at 450 Clout and one pack per unique opposing crew, not a client-supplied amount.

In regular combat, the 2014 receipt actually exposes the opponent; descriptions derive from the action being prepared. Combo counts use the committed count. Impacts use saved events, and unsupported pot multipliers / press-conference shortcuts are removed. The shared rotating deck is described as such, not as a building-unlock system.

Validation covers old-save decoding, every legal four-statement sequence, all three endings, rejected or stale actions, lost-response retries, shared Worker input validation, real SQLite cloud persistence and reward uniqueness. Desktop/mobile browser review must be reported separately: automated browser access was blocked by permission-review capacity/timeouts during implementation, so responsive CSS is not a claim of completed visual QA.
